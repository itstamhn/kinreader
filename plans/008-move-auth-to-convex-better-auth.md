## Why this matters

This closes three audit findings at once, and it is the only plan that can close them
properly.

1. **`convex/routers/users.ts` trusts a `userId` argument.** `getUserPlaylist` (line 64)
   and `saveUserProgress` (line 96) read and write any user's data by id, and
   `upsertUser` (line 6) mints a 30-day session token for *any* email with no
   verification. There is no `ctx.auth` call anywhere under `convex/`. The Convex
   guidelines are explicit: "NEVER accept a `userId` or any user identifier as a function
   argument for authorization purposes."
2. **The hand-rolled auth flow** in `src/server.ts` (magic link, Google OAuth, an
   in-memory `authCodes` Map) is the thing plan 003 patches. Once Better Auth issues real
   sessions, that whole surface is deleted rather than repaired.
3. **Per-user data is impossible today.** The library lives in `localStorage`, so nothing
   syncs across devices. `userArticles` in `convex/schema.ts:58` is modelled and unused.

kitcn already ships the machinery. `convex/generated/auth.ts` imports from `kitcn/auth`
and currently instantiates a **disabled** runtime with the reason
`getGeneratedAuthDisabledReason("missing_auth_file", "convex/auth.ts")`. The framework is
waiting for a `convex/auth.ts` that does not exist yet.

Better Auth matters specifically because `ctx.auth.getUserIdentity()` needs a JWT issuer
with OIDC discovery — Convex fetches `{domain}/.well-known/openid-configuration`. The
current bespoke tokens are not that, which is why "just call ctx.auth" was never an
option.

## Relationship to plan 003 — read this before starting

Plan 003 fixes the live auth bypass by having the client verify its token server-side,
with the token store moved to Workers KV. **003 should ship before this plan**, because
the bypass is trivially exploitable today and this migration is long.

This plan then **supersedes** 003's mechanism: the KV namespace, the `AUTH_CODES`
binding, and the `putAuthRecord`/`getAuthRecord`/`deleteAuthRecord` helpers all get
deleted here. That is roughly 40 lines of deliberate throwaway, accepted so the critical
hole closes in hours rather than sessions. When you finish, mark 003 SUPERSEDED in the
index — not REJECTED; it did its job.

## Current state

- `convex/generated/auth.ts` — kitcn's generated auth shim, currently disabled. Do not
  hand-edit it; it is regenerated by `kitcn codegen`.
- `convex/auth.ts` — **does not exist**. Creating it is the core of this plan.
- `convex/schema.ts:5` `users` and `:69` `sessions` — hand-rolled tables. Better Auth
  manages its own; expect to reconcile or drop these rather than keep both.
- `src/server.ts:6` `authCodes`; `:16` magic-link; `:71` verify; `:129` Google init;
  `:145` Google callback. All of this goes away.
- `src/components/AuthModal.tsx:39,67,186` — the three client entry points.
- `src/App.tsx:317` — the auth `useEffect` (rewritten by plan 003; rewritten again here).

Convex auth requirements from `convex/_generated/ai/guidelines.md`:

- `convex/auth.config.ts` is mandatory. Without it `ctx.auth.getUserIdentity()` always
  returns `null`.
- Prefer `identity.tokenIdentifier` over `identity.subject` for any ownership check.
- Use `ConvexProviderWithAuth`, not plain `ConvexProvider`, when auth is in play — plain
  `ConvexProvider` does not send tokens. Note this **changes what plan 006 wired**.

## Scope

**In scope**: `convex/auth.ts` (create), `convex/auth.config.ts` (create),
`convex/routers/users.ts` (rewrite with identity-derived ownership), `convex/schema.ts`
(reconcile user/session tables), `src/main.tsx` (swap to `ConvexProviderWithAuth`),
`src/App.tsx`, `src/components/AuthModal.tsx`, `src/server.ts` (delete the auth routes),
`wrangler.jsonc` (drop the `AUTH_CODES` KV binding), tests.

**Out of scope**: `/api/tts` (plan 007), `/r/:id` and `/api/og` (plan 009), the reader UI,
and any new product surface (sharing, teams, paid tiers). The `tier: 'pro'` default that
every user currently gets is a **product** decision — preserve current behaviour and
raise it separately rather than deciding it inside a security migration.

## Steps

### Step 1: Stand up Better Auth

Create `convex/auth.ts` using `defineAuth` from `convex/generated/auth.ts`, and
`convex/auth.config.ts` pointing at the issuer. Follow the current kitcn and Convex docs
for both files — do not write these from memory.

**Verify**: `bunx kitcn codegen` exits 0 and `convex/generated/auth.ts` no longer reports
`missing_auth_file`. `bunx convex dev --once` deploys.

### Step 2: Prove identity reaches the server

Add one temporary query that returns
`(await ctx.auth.getUserIdentity())?.tokenIdentifier ?? null`, sign in from the client,
and confirm it returns non-null. Remove the probe afterwards.

**Verify**: the probe returns a `tokenIdentifier` while signed in and `null` while signed
out. Do not proceed until both hold — every later step is built on this.

### Step 3: Rewrite `convex/routers/users.ts` around identity

Every procedure derives the user from `ctx.auth.getUserIdentity()`. No procedure accepts
a `userId` argument. `getUserPlaylist` takes no user argument at all; `saveUserProgress`
takes only the article and progress, and verifies the `userArticles` row belongs to the
caller before patching. Delete `upsertUser` — Better Auth owns account creation.

**Verify**: `grep -n "userId: v.id('users')" convex/routers/users.ts` → **no matches in
any `args` block**. `bun run typecheck` exits 0.

### Step 4: Swap the client provider and rewrite the auth UI

`src/main.tsx` moves from `ConvexProvider` to `ConvexProviderWithAuth` (or kitcn's
equivalent). `AuthModal.tsx` calls Better Auth's flows instead of `/api/auth/*`.
`src/App.tsx`'s URL-token `useEffect` is deleted outright — Better Auth owns the session,
and no token should ever be read from the query string again.

**Verify**: `grep -c "auth_token" src/App.tsx` → `0`. `grep -c "api/auth" src/` → `0`.

### Step 5: Delete the hand-rolled auth backend

Remove from `src/server.ts`: `authCodes` and the KV helpers, `/api/auth/magic-link`,
`/api/auth/verify`, `/api/auth/google`, `/api/auth/google/callback`. Remove the
`AUTH_CODES` KV binding from `wrangler.jsonc`. Decide whether `src/lib/autosend.ts` is
still used; if not, delete it too.

**Verify**: `grep -c "authCodes" src/server.ts` → `0`; `grep -c "AUTH_CODES" wrangler.jsonc`
→ `0`; `bun test` passes; `bun run build` exits 0.

## Test plan

The negative cases are the point of this plan — a passing happy path proves nothing here.

- An unauthenticated call to `getUserPlaylist` returns empty or throws; it never returns
  another user's rows.
- With two mocked identities A and B: A cannot read B's playlist, and A cannot patch a
  `userArticles` row owned by B. Both must fail even when A supplies B's document id
  directly — this is the regression test for the current defect.
- A signed-in user reads and writes their own progress successfully.
- Use `convex-test` with mocked identities; make no live network calls.

## STOP conditions

Stop and report if:

- `ctx.auth.getUserIdentity()` returns `null` while signed in (Step 2 fails). Everything
  downstream is unsafe until this works — **do not** fall back to passing a `userId`
  argument "temporarily". That is the exact vulnerability being fixed.
- Migrating existing users out of the hand-rolled `users` table would lose data. Report
  the count and the options; do not improvise a migration.
- kitcn's Better Auth adapter is incompatible with the installed versions.
- You cannot delete an auth route because something still calls it.

## Maintenance notes

- The rule this establishes: **no Convex function ever takes a user identifier as an
  authorization argument.** Every future procedure derives identity from
  `ctx.auth.getUserIdentity()`. A reviewer should reject any PR that reintroduces one.
- With identity in place, the per-user library (`userArticles`) becomes buildable — that
  is the cross-device sync the product has been missing, and it is the natural next plan.
- `tier: 'pro'` for everyone is preserved here deliberately. Revisit it as a product
  decision, not as a side effect.
