## Scope notes worth knowing before you start

- **003 fixes two findings, not one.** The audit found both the auth bypass (the client
  trusts the URL) and an ephemeral token store (a module-scope `Map` on Cloudflare
  Workers, where isolates are per-colo and short-lived). They are folded into one plan
  because fixing only the bypass routes users through `/api/auth/verify`, which then
  fails intermittently against the in-memory store — converting a security hole into a
  flaky login. Shipping either half alone leaves the app insecure or broken.
- **004 also covers the `/api/og` SVG**, which was a separate audit finding. Same file,
  same defect, one shared `escapeHtml` helper. Splitting it would produce two
  conflicting diffs against `src/server.ts` for no benefit.
- **005 deliberately does not add auth to `/api/tts`.** Anonymous listening is the
  current front-door experience; rate limiting is the fix that does not change the
  product.

## Findings not planned in this batch

Real, confirmed findings that were audited and left out of this round. Recorded so they
are not re-audited from scratch next session.

- **Convex functions trust a `userId` argument** — `convex/routers/users.ts:64` and
  `:96` read and write any user's playlist by id, and `:6` mints a 30-day session token
  for any email with no verification. There is no `ctx.auth` call anywhere under
  `convex/`. Not planned this round because `src/` never imports Convex, so it is not
  reachable through the app — but the functions are public on the deployment. Plan this
  before wiring the frontend to Convex.
- **SSRF in `/api/extract`** (`src/server.ts:216`) — fetches an arbitrary user-supplied
  URL server-side and returns the body, with no scheme or host validation. Contained on
  Workers; reaches localhost and link-local addresses on the `bun src/server.ts`
  self-hosted path.
- **Weak magic-link code** — `src/server.ts:38` generates the 6-digit code with
  `Math.random()` rather than a CSPRNG, and `/api/auth/verify` has no attempt limiting
  or lockout, so it is brute-forceable. Plan 003 does not make this worse but does not
  fix it.
- **ElevenLabs key read from the wrong place** — `src/server.ts:588` uses
  `process.env.ELEVENLABS_API_KEY` while every other provider reads
  `(request as any).env`. Workers secrets are not in `process.env`, so that provider is
  silently dead in production.
- **Extraction logic duplicated and diverging** — ~120 lines in `src/server.ts:216`
  versus `convex/routers/articles.ts:4`; the server copy has a direct-HTML fallback the
  Convex copy lacks, and the Convex copy is dead code.
- **No CI** — plan 002 adds `typecheck` and `test` as scripts but wires no automation.
  Nothing enforces them on push.
- **No React error boundary** — any render throw blanks the entire page, which is why
  the plan-001 bug was total rather than local.

## Product direction (not defects — options to weigh)

- **The Convex backend is fully designed and completely unwired.** `articles`,
  `audioTracks`, `userArticles` and `sessions` are all modelled in `convex/schema.ts`;
  `src/` imports none of it and runs entirely on `localStorage`. Connecting it is the
  single biggest unlock — cross-device library and reading progress.
- **Audio cache is `sessionStorage`**, so paid TTS regenerates on every tab close
  (`src/lib/storage.ts:88`). The `audioTracks` table is already keyed by
  `articleId + voice + speed` for exactly this. Moving the cache server-side is a cost
  win and a latency win at once, and it shrinks what plan 005 is defending.
- **Share links are cosmetic.** `/r/:id` renders a rich card, but `id` only becomes
  `?read=` and nothing resolves it — a recipient cannot actually open the shared
  article.
